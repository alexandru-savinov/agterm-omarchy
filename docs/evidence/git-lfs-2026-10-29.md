## Why a separate repository

An initial upload to this public application fork transferred zero bytes and exited with:

```text
@alexandru-savinov can not upload new objects to public fork alexandru-savinov/agterm-omarchy
```

The coordinator authorized a dedicated non-fork fixture repository after this observed capability restriction.
GitHub's repository API verifies the new repository is public and `fork=false`.
The existing application's fork relationship, visibility, history, and upstream objects were preserved.
No unavailable LFS pointers were pushed to the application fork.
Only the fixture directory's PNG files are tracked through LFS; unrelated assets were not migrated.
